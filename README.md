# Tasks

A basic Next.js App Router app with Prisma and PostgreSQL. Create, view, rename, and delete tasks, with due dates, priority, completion, and category controls. There are no users or authentication; everyone with access to the app shares the same list.

This is the demo app for [ForkDB](https://github.com/xavierloeraflores/forkdb-proto), with a database baseline for demonstrating separate database forks in Git worktrees.

## Run locally

Use Node.js 24 and pnpm. With Docker running:

```sh
cp .env.example .env
pnpm install
pnpm db:up
pnpm db:deploy
pnpm dev
```

Open http://localhost:3000. If that port is in use, Next.js prints the port it selects.

The Docker database uses port 5433 and a persistent volume. `pnpm db:down` stops it without deleting data. If you already have PostgreSQL, create an empty database and set `DATABASE_URL` in `.env` to its connection string instead of running `pnpm db:up`.

### This checkout

This checkout is already configured with a separate Postgres.app database on `127.0.0.1:55433`. Its files are in the ignored `.postgres/` directory, and `.env` points to it. Run `pnpm db:deploy` after pulling schema changes, then `pnpm dev` while that database is running. Keep the existing `.env` when using it.

To restart that database after a reboot, run from this folder:

```sh
pg_ctl -D .postgres/data -l .postgres/server.log -o "-p 55433 -h 127.0.0.1 -k $PWD/.postgres/socket" start
```

Stop it with `pg_ctl -D .postgres/data stop`. These commands require the Postgres.app tools on your PATH. This local development database trusts connections from this machine and listens only on loopback.

## Schema

The merged `tasks` table has seven columns:

| Field | Type | Default |
| --- | --- | --- |
| `id` | UUID primary key | Generated by Prisma |
| `name` | varchar, up to 200 characters | Required |
| `createdAt` | Timestamp with time zone | Current time |
| `dueAt` | Nullable timestamp with time zone | No date |
| `priority` | LOW, MEDIUM, or HIGH enum | MEDIUM |
| `completed` | Boolean | false |
| `category` | varchar, up to 32 characters | Personal |

Task names are trimmed and validated on the server. Tasks appear newest first. Delete asks for confirmation, and failed saves keep the entered text available to retry.

## Commands

```sh
pnpm lint
pnpm typecheck
pnpm fullbuild
pnpm start
pnpm db:studio
pnpm db:seed
```

`pnpm db:seed` inserts 15 example tasks. Repeating it skips existing example IDs and preserves their names and creation dates. It recreates deleted examples, so do not rerun it on forks when demonstrating independent changes.

The [database baseline and four-fork report](docs/database-baseline.md) records the original source, all 60 fork task rows, each schema change, branch commits, and a screenshot of all four apps running. The [JSON snapshot](docs/data/fork-snapshots.json) includes exact database contents and metadata. The original demo branches preserve the isolated feature variants; `main` combines all four features. ForkDB copies source data, while Git merges code and migrations. It does not merge live database rows.

After changing `prisma/schema.prisma`, run `pnpm db:migrate --name describe_change` and `pnpm db:generate`. Apply saved migrations in another environment with `pnpm db:deploy`.

`pnpm fullbuild` sets `NODE_ENV=production`, which avoids problems from a nonstandard shell environment. Building generates Prisma Client but does not require a running database. Runtime requests do require PostgreSQL and `DATABASE_URL`.
